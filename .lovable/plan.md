# تشغيل ومعاينة ونشر مشاريع وكيل البرمجة

## الهدف
جعل كل مشروع محفوظ في GitHub الخاص قابلًا للتشغيل والمعاينة والنشر فعليًا، مع بقاء كل التفاصيل داخلية ودون أي تعديل على واجهة Megsy.

## ما سيتم تنفيذه
1. **تشغيل المشروع**
   - عند بدء أو استكمال مهمة، تشغيل VM المشروع أو إنشاء VM جديد تلقائيًا.
   - إذا كانت البيئة جديدة، استعادة الملفات من مستودع GitHub الخاص ثم تثبيت الاعتمادات.
   - تشغيل Vite على المنفذ العام والتأكد من جاهزيته بدل افتراض أنه يعمل.

2. **المعاينة الحية**
   - تحديث `preview_url` عند كل تشغيل، بما في ذلك حالة استبدال VM منتهٍ.
   - إجراء فحص جاهزية داخلي وإعادة تشغيل خادم التطوير عند توقفه.
   - إبقاء رابط المعاينة مرتبطًا بالمشروع نفسه عبر الجلسات.

3. **النشر**
   - إزالة اعتماد النشر على `repo_id` الخاص بمستودع Freestyle القديم.
   - بعد نجاح `npm run build`، قراءة ملفات `dist` ونشرها مباشرة عبر خدمة النشر.
   - تسجيل رابط النشر ونسخة GitHub المنشورة في `dev_projects` و`dev_deploys`.
   - عدم إعادة النشر إذا كان آخر commit منشور هو نفسه، وإعادة استخدام الرابط الحالي.

4. **الاستمرارية والأمان**
   - يبقى GitHub الخاص هو مخزن ملفات المصدر الوحيد.
   - لا تصل مفاتيح GitHub أو مفاتيح التشغيل إلى المتصفح.
   - فشل المعاينة أو النشر يُسجل بوضوح ولا يمسح ملفات المشروع أو آخر نسخة ناجحة.

## التحقق
- إنشاء مشروع جديد وتشغيله وفتح رابط المعاينة.
- إيقاف/فقد VM ثم التأكد من الاستعادة من GitHub وإعادة التشغيل.
- نشر المشروع والتحقق من الرابط العام ومحتوى النسخة المبنية.
- تعديل المشروع ثم نشر commit جديد، والتأكد أن إعادة طلب النشر دون تغييرات لا تنشئ نسخة زائدة.
